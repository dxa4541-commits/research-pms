# Research Project Management System — Full Description
# نظام إدارة المشاريع البحثية — الوصف الكامل

## 1. نظرة عامة / Overview
**AR:** تطبيق ويب يدير دورة حياة المشروع البحثي الجامعي كاملة: تسجيل الموضوع، رفع نسخ العمل، مراجعة الدكتور وملاحظاته، القبول أو الرفض أو طلب التعديل، التقييم، المواعيد النهائية، والتقارير. بُني انطلاقاً من مخططات حالات الاستخدام (Use Case) والأصناف (Class) والتسلسل (Sequence) الموجودة في مجلد `docs/`.

**EN:** A web application that manages the full lifecycle of a university research project: topic registration, version uploads, supervisor review and notes, approval / rejection / change requests, grading, deadlines and reports. It was built from the use-case, class and sequence diagrams in `docs/`.

## 2. المشكلة والهدف / Problem & goal
تتم متابعة الأبحاث عادةً عبر البريد والرسائل، فتضيع النسخ والملاحظات ولا يعرف أحد الحالة الحالية أو المتأخر. يوفّر النظام مكاناً واحداً يرى فيه كل طرف ما يخصه فقط، مع إشعارات وسجل كامل لكل نسخة.

## 3. المستخدمون والأدوار / Roles
| الدور / Role | الوصف / Description |
|---|---|
| **Student / الطالب** | يسجّل موضوع بحثه (فردي أو ضمن فريق) ويختار الدكتور المشرف، يرفع النسخ، ويتابع الحالة والملاحظات والدرجة. يرى أبحاثه وأبحاث فريقه فقط. |
| **Supervisor (Doctor) / الدكتور** | يقبل أو يرفض الموضوع، يطلب تعديلات، يضيف ملاحظات على كل نسخة، يقيّم البحث (0–100)، يحمّل الملفات، يتابع طلابه، ويكوّن الفرق. يرى الأبحاث المسندة إليه فقط. |
| **Admin / المسؤول** | يدير المستخدمين والأدوار والمقررات، يحدد المواعيد النهائية، يتعرف على الأبحاث المتأخرة، ويعرض تقارير التقدم. يرى كل الأبحاث. |

## 4. المزايا الرئيسية / Features
- **تسجيل الدخول** بجلسات تنتهي بعد 7 أيام وحماية من تخمين كلمة المرور.
- **تسجيل موضوع بحث** مرتبط بمقرر ودكتور مشرف.
- **رفع نسخ متعددة** من البحث، لكل نسخة رقم فريد لا يُستبدل (v1, v2, …).
- **فحص الملف (Check file):** يقبل PDF / DOC / DOCX فقط، بحد أقصى 10 ميجا، ويتحقق من محتوى الملف الفعلي وليس الامتداد فقط.
- **مراجعة الدكتور:** قبول / رفض / طلب تعديلات، وملاحظات نصية على كل نسخة.
- **التقييم:** درجة واحدة لكل بحث من 0 إلى 100، قابلة للتحديث.
- **الإشعارات:** تصل تلقائياً عند رفع نسخة، أو ملاحظة، أو قرار، أو تقييم، أو موعد، أو انضمام لفريق.
- **الفرق:** تكوين فريق من عدة طلاب لمقرر معين، ولكل فريق بحث واحد.
- **المواعيد النهائية:** يحددها المسؤول، ويُعلَّم البحث «متأخر» إذا انتهى الموعد وهو ما زال قيد الانتظار أو بانتظار التعديل.
- **التقارير:** إجمالي الأبحاث، التوزيع حسب الحالة، عدد مشاريع كل دكتور، متوسط الدرجات، والمتأخر.
- **بحث وتصفية** في القوائم (`status`, `q`, `limit`, `offset`).
- **واجهة بالعربية (RTL) والإنجليزية** مع التبديل من الأعلى.

> **تحديث / Update:** تمت إضافة مراحل مخصصة، تسليمات لكل مرحلة، تقييم بمعايير، رسائل خاصة للفرق، لوحة تحكم وتقارير للدكتور — انظر [SUPERVISOR_REQUIREMENTS.md](SUPERVISOR_REQUIREMENTS.md).
> Custom stages, per-stage submissions, rubric grading, private team messaging and a supervisor dashboard/reports were added.

## 5. دورة حياة البحث / Research lifecycle
```
تسجيل الموضوع ──► pending ──► (الدكتور)
                              ├─► approved            (مقبول)
                              ├─► rejected            (مرفوض)
                              └─► changes_requested   (مطلوب تعديل) ──► الطالب يرفع نسخة جديدة ──► يعود للمراجعة
```
الدكتور يضيف ملاحظات على أي نسخة ثم يقيّم البحث بدرجة نهائية.

## 6. البنية التقنية / Architecture
- **نمط MVC** كما في مخطط الأصناف:
  - **View:** `public/` — HTML/CSS/JS بدون أطر عمل (`app.js`, `core.js`, `views/`, `i18n.js`).
  - **Controller:** `src/controller.js` و`src/controllers/` (auth, research, review, admin, notifications).
  - **Model / Repository:** `src/db.js` (SQL) و`src/research.js`, `src/notifications.js`, `src/files.js`.
  - **Routing وفحص الصلاحيات:** `server.js` — كل مسار API له قائمة أدوار مسموحة.
- **بدون أي اعتمادات خارجية:** يحتاج Node.js 22.5+ فقط، ويستخدم `node:sqlite` المدمج.
- **قاعدة البيانات SQLite** (`data/app.db`) بوضع WAL، والملفات المرفوعة في `uploads/` بأسماء عشوائية.

### جداول قاعدة البيانات / Tables
`users`, `courses`, `teams`, `research`, `submissions`, `research_grades`, `notes`, `notifications`, `sessions`.

## 7. الأمان / Security
- كلمات المرور مشفّرة بـ scrypt.
- حد لمحاولات الدخول الفاشلة (5 لكل IP+بريد، 50 لكل IP كل 15 دقيقة → HTTP 429).
- ترويسات أمان (CSP, X-Frame-Options, nosniff, no-referrer) و`Cache-Control: no-store` للـ API.
- فحص الدور على كل مسار، وحصر الوصول لكل بحث بأصحابه (الطالب/الفريق/الدكتور المسند/المسؤول).
- لا تبقى ملفات يتيمة عند فشل الرفع، ورفع نسختين بالتزامن يعيد 409 بدل إفساد الترقيم.
- تنظيف الجلسات المنتهية كل ساعة، وإغلاق نظيف عند SIGTERM/SIGINT.

## 8. التشغيل والنشر / Run & deploy
```bash
npm start   # http://localhost:3000
npm test    # اختبار شامل لكل حالات الاستخدام
```
- حسابات تجريبية تُنشأ عند أول تشغيل (غيّرها!) — انظر `README.md`.
- للنشر: `Dockerfile` جاهز، ويتطلب قرصاً دائماً على `/data` والمتغير `ADMIN_PASSWORD` — التفاصيل في `DEPLOY.md`.
- لتصفير البيانات: أوقف الخادم واحذف `data/app.db` ومحتوى `uploads/`.
